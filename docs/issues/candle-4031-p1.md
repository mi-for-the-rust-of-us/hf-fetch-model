Following up on [@zsewasdsdsd's results](https://github.com/huggingface/candle/issues/4031#issuecomment-6159283670): I see the same on the release you reported (candle 0.11.1 from crates.io, CPU, f32), with the multilingual `openai/whisper-tiny` weights and a real `pcm_to_mel` output, compared stage by stage. The encoder output does not depend on the input's layout.

The three inputs are built as in the report: (a) a fresh `Tensor::from_vec(window, (1, 80, 3000))`; (b) `Tensor::from_vec(full, (1, 80, 342000)).narrow(2, s, 3000)`, a real strided view (`is_contiguous=false`, strides `[27360000, 342000, 1]`); (c) is (b) followed by `.contiguous()`. Before running, the program asserts that the window in (a) is bitwise equal to the narrowed values. With random values in a log-mel range, and with a `pcm_to_mel` output of 342 000 frames (from synthetic audio), at three offsets (`s` = 0, 171 000, 339 000), every comparison is exactly zero at every stage:

```
== mel(proper window) (narrow start=171000) nar.is_contiguous=false stride=[27360000, 342000, 1] offset=171000
   input maxabs(fresh,narrow)=0e0  bitwise-equal=true
   conv1+gelu  fresh-vs-narrow=0e0          narrow-vs-narrow.contig=0e0          fresh-vs-narrow.contig=0e0
   conv2+gelu  fresh-vs-narrow=0e0          narrow-vs-narrow.contig=0e0          fresh-vs-narrow.contig=0e0
   encoder     fresh-vs-narrow=0e0          narrow-vs-narrow.contig=0e0          fresh-vs-narrow.contig=0e0
```

That matches the code. Only `conv1` ever sees the strided tensor ([`model.rs` L281-L300](https://github.com/huggingface/candle/blob/cfcbd7186d13271843ce7eb41d25659bd0835850/candle-transformers/src/models/whisper/model.rs#L281-L300)), and its output is freshly allocated. On CPU, conv1d goes through im2col ([`cpu_backend/mod.rs` L2831-L2847](https://github.com/huggingface/candle/blob/cfcbd7186d13271843ce7eb41d25659bd0835850/candle-core/src/cpu_backend/mod.rs#L2831-L2847)), and `Im2Col1D` reads the input through its layout's offset and strides ([L1096-L1111](https://github.com/huggingface/candle/blob/cfcbd7186d13271843ce7eb41d25659bd0835850/candle-core/src/cpu_backend/mod.rs#L1096-L1111)). That code is the same in 0.11.0, 0.11.1 and today's `main`.

What does give a difference of the same order as yours (21.9) is a fresh window built with the wrong layout. `pcm_to_mel` returns a bin-major `[80][n_frames]` buffer, and the official example narrows it exactly as your strided path does ([`whisper/main.rs` L445](https://github.com/huggingface/candle/blob/cfcbd7186d13271843ce7eb41d25659bd0835850/candle-examples/examples/whisper/main.rs#L445)). If instead the fresh window is a flat slice of that buffer (`mel[s*80..(s+3000)*80]`), or a time-major `(3000, 80)` buffer passed as `(1, 80, 3000)`, the encoder outputs differ by maxabs 23.2 to 23.7, with the narrowed path the correct one. To @zsewasdsdsd's question about where it starts: in that case, `conv1` already differs, because its input does (output trimmed to the input and encoder lines):

```
== MISTAKE flat-slice all_mel[s*80..(s+3000)*80] (narrow start=0) nar.is_contiguous=false stride=[27360000, 342000, 1] offset=0
   input maxabs(fresh,narrow)=1.927191e0  bitwise-equal=false
   encoder     fresh-vs-narrow=2.3244848e1  narrow-vs-narrow.contig=0e0          fresh-vs-narrow.contig=2.3244848e1
== MISTAKE time-major buffer read as (1,80,3000) (narrow start=0) nar.is_contiguous=false stride=[27360000, 342000, 1] offset=0
   input maxabs(fresh,narrow)=1.8521403e0  bitwise-equal=false
   encoder     fresh-vs-narrow=2.3723381e1  narrow-vs-narrow.contig=0e0          fresh-vs-narrow.contig=2.3723381e1
```

That would fit your symptoms (good transcripts from the narrowed path, garbage from the fresh one), but not your observation that narrow-then-`.contiguous()` agrees exactly with the fresh tensor: here `.contiguous()` always agrees with the narrowed view. Could you check, right before the encoder, that your fresh tensor and `mel_full.narrow(2, 0, 3000).contiguous()` are elementwise equal (for example `(fresh - narrowed)?.abs()?.max_all()?`), and share how the fresh `mel` is built, the exact candle version and features (`cuda`, `cudnn`, `mkl`), the dtype, and whether you use `whisper::model` or `whisper::quantized_model`? I haven't tested CUDA.
